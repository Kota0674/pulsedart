# Publishing to GitHub: what goes in, what never does

The public repository should contain **only our own work**. Everything derived byte-for-byte
from HyperX/PixArt firmware, and every private key, stays local. `.gitignore` enforces this;
check `git status` before every commit anyway.

## Never publish

| Path | Why |
|---|---|
| `dump/` (flash.bin, eeprom.bin, uicr/ficr, dongle/, app.asm, logs) | Stock firmware images (copyright HyperX/HP/Kingston), device-unique data (FICR, pairing records, BLE identity) |
| `fw/mouse/src/stock_blobs.c`, `re/srom_pmw3389*.bin` | PixArt sensor firmware (proprietary). Users generate it from their own dump with `tools/extract_blobs.py`. |
| `re/led_tables.h`, `re/ram_init.bin`, `re/tools/*.bin` | Tables and data copied from the stock firmware. Generated by the same script. |
| `re/tools/out/`, `re/tools/*.lst`, `re/tools/*.txt` listings | Full disassembly of the stock firmware |
| `fw/keys/*.pem` | **MCUboot signing key.** Anyone with it can sign firmware for this bootloader. Keep a private backup. |
| `fw/mouse/local.conf` | Personal settings (the author's dongle record) |
| `fw/*/build*/` | Build output |
| `pi_wiring*.png` | Based on a third-party Raspberry Pi pinout image; replaced by our own `docs/img/*` |

## Fine to publish

- All firmware sources in `fw/` except the two generated headers above, plus board files,
  Kconfig and scripts.
- `pi/` scripts and OpenOCD configs, and `tools/`.
- `re/*.md`: our own analysis. It quotes addresses, register values, protocol bytes and short
  constants, which is normal interoperability documentation. Checked on 2026-09-27: the longest
  byte runs in the notes (≤ 64 bytes) are the USB HID report descriptors and example protocol
  replies (in `input_usb_led.md`, `vendor_protocol.md`), needed for compatibility. The notes
  contain no code dumps, and no full tables or SROM.
- `docs/`.

## Personal data check before the first push

- The author's address or e-mail must not appear in any file (git commits will carry the author
  name set in git config; choose it deliberately).
- Wi-Fi, IP addresses, host names, user names of the programmer Pi: the docs use `<pi>`;
  grep for your own before pushing (checked clean on 2026-09-27).
- Radio pairing addresses of my dongles are replaced by made-up ones (`4a 91 3c d7`,
  `6e 2f 90 c4`, `6e 2f 15 41`) everywhere, together with the values derived from them.

## Releases

Tags start at `v0.4.1`; the earlier versions in `CHANGELOG.md` were never tagged.

A release attaches the three files that `fw\build-release.ps1` writes to `release/v<version>/`
(plus `SHA256SUMS`). They are built with marker bytes instead of the SROM and the LED tables,
so they contain none of that data; `tools/make_firmware.py` completes them from the user's own
dump. Before attaching, check that the files really are clean:
- the build must come from `build-release.ps1`, never from `build.ps1` / `build-mcuboot.ps1`
  (those link the real data);
- `release/` is in `.gitignore`: the binaries go to the GitHub release page, not into git.

The release MCUboot contains the author's **public** key and the release image the author's
signature. Both are harmless to publish, and `make_firmware.py` replaces them with the user's.
